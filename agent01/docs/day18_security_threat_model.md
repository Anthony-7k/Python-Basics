# Day 18 安全威胁模型与可靠性边界

## 1. 范围与安全目标

本威胁模型覆盖 FastAPI 的知识库、文档、入库任务、会话与 Chat 接口，
以及这些接口访问的 MySQL、上传目录、Chroma、Redis、LLM 和 Embedding
服务。目标是建立可测试的演示级边界，不把它描述为生产级多租户安全方案。

核心安全目标：

- 未认证请求不能进入 `/api/v1/**` 业务接口，`/health` 与 `/ready` 保持公开。
- 请求身份必须从 Bearer Token 得到，服务层不能依靠固定默认用户判断权限。
- 用户只能访问自己拥有的知识库，以及该库的文档、任务和会话。
- 上传和 Chat 的资源消耗有配置化上限，超限响应可追踪。
- 日志不记录凭证、完整问题、回答、Prompt 或文档正文。
- 文档证据按不可信数据处理，不能改变认证、授权或系统指令。

## 2. 资产、入口、攻击者与信任边界

### 资产

- 知识库内容、文档文件、向量与会话历史。
- Bearer Token、LLM/Embedding API Key 和数据库凭证。
- 用户身份、知识库归属关系、请求与错误日志。
- API、模型和数据库的可用性与费用预算。

### 入口

- `/api/v1/knowledge-bases/**`
- `/api/v1/documents/**` 与 `/api/v1/ingestion/**`
- `/api/v1/conversations/**`
- `/api/v1/chat`
- 上传文件名、扩展名、MIME、文件内容、用户问题和检索证据。

### 攻击者能力

- 无凭证或持有某个演示 Token 的网络调用者。
- 能猜测其他用户的 `knowledge_base_id`、`document_id`、`task_id` 或
  `conversation_id`。
- 能上传带恶意文件名、超大内容或 Prompt Injection 文本的文档。
- 能重复调用上传与 Chat，尝试耗尽进程、模型额度或存储。

### 信任边界

1. HTTP 边界：Bearer Token 只在认证依赖中解析，不进入业务日志。
2. 服务边界：`AccessControlService` 根据请求用户和数据库归属校验资源。
3. 检索边界：通过授权后仍按 `knowledge_base_id` 过滤 Chroma 数据。
4. 生成边界：系统 Prompt 高于用户问题和 `<knowledge_base_evidence>` 数据。
5. 外部服务边界：LLM、Embedding、MySQL、Redis 和 Chroma 均不是本进程内
   的完全可信组件，需要各自的凭证、网络和可用性控制。

## 3. 威胁与当前缓解

| 威胁 | 当前缓解 | 验证方式 | 剩余风险 |
| --- | --- | --- | --- |
| 未认证访问 | `/api/v1/**` 的服务依赖要求 Bearer 身份 | 缺失/错误/正确凭证测试 | Token 是静态演示凭证，无轮换、吊销和 MFA |
| 跨用户越权/资源枚举 | 服务层统一校验所有者；越权与不存在均返回 404 | 两用户知识库、文档、任务、会话和 Chat 测试 | 无组织、角色、共享授权或策略审计 |
| 恶意文件与路径穿越 | 扩展名/MIME/空文件/大小校验；哈希文件名；只保留 basename | 上传和文件名回归测试 | 未做杀毒、沙箱解析、内容类型魔数和压缩炸弹检测 |
| 资源耗尽 | 上传与 Chat 按用户、按入口做进程内固定窗口限流 | 独立 scope/user 与 429 测试 | 多进程/多实例不共享状态，重启会清空计数 |
| 日志泄密 | JSON 字段白名单；Bearer/API Key/已配置密钥脱敏；不记录正文 | 格式器脱敏测试 | 第三方库、基础设施或未来新增日志仍需持续审计 |
| Prompt Injection | 系统规则、证据标签、程序侧授权、来源约束、确定性测试 | 恶意证据边界和跨用户 Chat 测试 | 模型仍可能被诱导；不能保证完全防御 |
| 上游超时/故障 | LLM/Embedding 超时和通用 502/504 响应 | 既有 API 测试 | 无熔断、预算配额、重试退避或跨区域容灾 |
| 密钥进入 Git | `.env` 不提交，示例仅用占位符，测试不使用真实密钥 | Git diff/历史扫描与人工检查 | 仍需生产密钥托管和自动 secret scanning |

## 4. 安全设计决策

- Bearer Token 到邮箱的映射只从 `DEMO_AUTH_USERS_JSON` 环境变量读取。
- 认证后的 `AuthenticatedUser` 通过 FastAPI 依赖注入业务服务；没有显式
  `knowledge_base_id` 时，`DEFAULT_KNOWLEDGE_BASE_NAME` 只决定该请求用户的
  默认库名称，不决定请求身份。
- `AccessControlService` 是知识库和会话的统一授权入口。文档与入库任务先
  解析所属知识库，再复用相同的所有者校验。
- 越权统一返回 404，减少资源枚举信息；日志只记录不可逆 `actor_id`。
- 限流只在认证后计数，避免把原始 Token 作为内存键或日志字段。
- Prompt 边界是纵深防御的一层，不能替代程序侧权限、工具白名单和输出校验。

## 5. 上线前仍需完成

- 用 OIDC/OAuth2、短期令牌、密钥轮换、MFA 与细粒度 RBAC/ABAC 替换演示认证。
- 在 API 网关或 Redis 中实现分布式限流、请求体上限、连接并发和成本配额。
- 使用密钥托管服务、WAF、恶意文件扫描、隔离解析和内容安全策略。
- 把结构化日志接入集中审计、告警和保留策略，并执行自动 secret scanning。
- 对 Prompt Injection 做持续红队、模型升级回归、工具参数校验和输出策略检查。
