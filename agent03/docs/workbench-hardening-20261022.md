# 审查闭环加固 · 2026-10-22

## 本轮范围

本轮优先处理用户五组 Qwen-Plus 模拟审查中发现的展示与审批一致性问题，不扩展成生产上线验收。

### 风险轮次与审批

原审批查询统计案件所有历史轮次的 OPEN 高风险。人工修正字段并重跑规则后，风险页面使用最新轮次、审批却仍可能被旧风险拦住。

现审批与风险页面共用最新轮次查询。历史风险不删除、不自动改为已解决。当前轮次仍存在 OPEN 高风险时返回 409；没有审查结果时也拒绝批准。风险接受只属于当轮，新一轮规则重跑重新产生的风险必须重新处置。

新增回归链路：异常主体 → 人工字段修正 → 当前风险清空 → 批准 → 报告 READY → 下载成功；以及旧风险处置被拒绝、旧轮次接受不能绕过新风险、无审查结果不能批准。

### 多份单据展示

比对接口为每列返回：

| match_status | 含义 | 展示行为 |
| --- | --- | --- |
| MATCHED | 唯一文档且有完成的抽取 | 展示字段 |
| MISSING | 无对应分类文档 | 提示缺少材料 |
| AMBIGUOUS | 多份同类文档 | 展示全部候选文件名，不展示任意一份字段 |
| UNAVAILABLE | 已分类文档但无完成的抽取 | 提示抽取未就绪 |

候选项包含文档 ID、原文件名和解析状态。跨租户比对接口仍返回 404。本轮没有实现人工选单、合并发票、金额分摊或更改高风险阻断策略。

### 工作台

字段和五类风险增加中文名称，保留规则代码便于排查；常见审批、版本与过期风险错误转为中文，保留追踪编号。取消工作台中未校准的固定概率展示，模型来源和 Token 用量继续显示。未知后端错误仍保留原消息，不猜测原因。

前端测试使用项目现有 TypeScript 编译器及 Node 测试运行器，执行实际组件的静态渲染和展示函数测试，不额外增加依赖；不是浏览器点击端到端测试。

## 验收与边界

- 后端完整回归 92 项通过，总覆盖率 91.11%；本轮修改文件静态检查通过。依赖仍有 Starlette 测试客户端弃用提示，不影响测试结果。
- 前端 8 项测试通过，类型检查和生产构建通过；仍有约 994 KB 的主包体积警告。
- 新服务 `/health/ready` 和首页均返回 200；对既有演示案件只读核对，检出 2 个多份候选列和 2 个真正缺失列，均符合新接口语义。
- 本机保留 15 条 `cloud-grounded-v1` 抽取记录；用户截图中的五种模拟场景结果符合预期，金额超限批准请求被拦截。不能据此宣称真实业务准确率 100%。
- 本轮自动化使用临时数据库、Fake/Mock Provider，不会发送业务文档到云端，也不额外产生模型调用费用。真实 RapidOCR 测试使用本地推理。
- 既有工作台案件只做读取核对，没有自动处置风险或审批任何现有案件。
- Docker、生产病毒扫描、独立真实业务测试集、并发多用户验收仍是未完成项。
